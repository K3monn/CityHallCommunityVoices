# City Hall & Community Voices — Unity Project Scaffold

This is a **project scaffold**, not a finished, buildable Unity project. Treat it as a strong starting point that still needs an Editor pass — see "Known limitations" at the bottom before you assume anything is final.

What you get:
- A proper `Assets/` folder layout and a `Packages/manifest.json` pre-loaded with the packages this project needs (XR Interaction Toolkit, OpenXR, URP, AI Navigation, TextMeshPro, ProBuilder).
- 20 C# scripts covering NPC variation, time-of-day routines, the interaction/dialogue system, ambient audio, performance culling, and portal travel between the plaza and the City Hall interior.
- Written content as JSON data files: 14 NPC conversations, 7 civic exhibits, 21 environmental-storytelling boards/posters/signs, and a 26-NPC roster — all pulled from the original design brief.
- `Assets/Scripts/Editor/TownSceneBuilder.cs` — an Editor menu command (**City Hall > Build Town Scene**) that procedurally assembles the *entire* town — residential neighborhood, Main Street, public buildings row, City Hall plaza and interior, all NPC spawn points, all boards/exhibits, the player rig, NavMesh, and lighting — into a real, playable `Assets/Scenes/Town.unity` in about 30 seconds. See section 3.
- This README, which is the part that actually gets you from "files on disk" to "something running on a headset."

---

## 1. Prerequisites

- **Unity Hub** + **Unity 2022 LTS** (2022.3.x). 2023 LTS also works; adjust package versions in `Packages/manifest.json` if the Editor complains about a specific version not existing — Package Manager will offer the nearest compatible one.
- **Android Build Support** module (with the Android SDK, NDK, and OpenJDK sub-modules checked) installed via Unity Hub — required for a Quest/Android XR build. Your machine already has `.android` and `AndroidStudioProjects` folders, so some of this tooling may already be present; Unity still needs its own copies installed through Hub.
- A Meta Quest (or other OpenXR headset) with Developer Mode enabled, or the Meta Quest Link / Android Studio's ADB for deploying builds.
- **Creative Characters — Modular Animated Pack** purchased on your Unity account (https://assetstore.unity.com/packages/3d/characters/humanoids/creative-characters-modular-animated-pack-304838). I could not access the Asset Store from the environment that wrote this project, so the pack itself is not included — you'll import it yourself in step 3.

## 2. Create the actual Unity project

Unity project files (`ProjectSettings/`, the `.sln`, etc.) are normally generated by the Editor itself, not hand-written — so:

1. In Unity Hub, **New Project** → **3D (URP)** template → name it `CityHallCommunityVoices` → create it anywhere on disk.
2. Close Unity once it finishes opening.
3. Copy this scaffold's `Assets/` folder and `Packages/manifest.json` into the new project folder, **merging** with (overwriting) the ones Unity generated. This scaffold doesn't include a `ProjectSettings/` folder at all — keep the one Unity generated for you untouched.
4. Reopen the project in Unity. Package Manager will resolve XR Interaction Toolkit, OpenXR, AI Navigation, etc. automatically — this can take a few minutes on first open.
5. **Edit > Project Settings > XR Plug-in Management** → install/enable the **OpenXR** provider (or Oculus, if you prefer Meta's native path) for the Android platform.

## 3. Build the town automatically

Once the project opens with no compile errors (Package Manager needs to finish resolving first), go to the Unity menu bar: **City Hall > Build Town Scene**.

This runs `TownSceneBuilder.cs` and, in about 30 seconds, procedurally assembles the whole town into `Assets/Scenes/Town.unity` and opens it:

- Ground, road, sidewalks, streetlamps, crosswalks along the full residential → commercial → public-row → plaza spine.
- Every building described in the brief (houses, duplex, apartment block, all 9 Main Street shops, the 6 public buildings, Transit Station, City Hall exterior with flag/benches/flower beds/art/memorial/donation box) as simple primitive block-outs.
- All 21 boards/posters/signs and all 7 City Hall civic exhibit kiosks, wired live to `Boards.json` / `CivicExhibits.json` — click any of them in Play mode and the real written content shows up.
- All 26 roster NPCs spawned at hand-placed positions via `NPCSpawner`, standing in as capsule placeholders (see section 5 to swap in the real asset pack).
- A `PlayerRig` + `Main Camera` with `PlayerInteractor` already wired for mouse/keyboard testing, positioned at the residential end of the street facing City Hall.
- A `Systems` object with `CivicDataLoader`, `TimeOfDayManager` (already pointed at a sun light), and `PerformanceLODManager` (already pointed at the player camera) all wired up.
- Two `PortalTravel` archways — one at the City Hall entrance, one at the interior exit — that hide/show the town vs. the interior and teleport the player between them.
- A baked NavMesh for both the outdoor town and the interior lobby.

**Press Play.** WASD + mouse to move/look, left-click to interact with people, boards, and exhibits, walk through the blue archway at the City Hall entrance to reach the interior. This is the real town, not a stripped-down test — everything past this point is refinement, not construction.

Why an Editor script instead of a hand-written scene file: Unity's `.unity` scenes are a fragile, GUID-heavy serialization format with no way to verify correctness outside the Editor itself. A script that calls Unity's own `GameObject.CreatePrimitive`/`PrefabUtility`/`NavMeshSurface` APIs is guaranteed to produce a structurally valid scene, because Unity is the one actually building it — I only had to get the C# right, which is checkable, rather than hand-authoring YAML, which isn't. The tradeoff is the geometry itself: everything is Unity's built-in primitives (cubes, cylinders, spheres, planes, capsules), so houses have flat cap roofs instead of pitched ones, buildings have no interior detail, and there's no hand-authored mesh anywhere in it — see the class-level comment in `TownSceneBuilder.cs` for why (a mis-wound custom mesh renders invisible from outside, and that's not verifiable without opening it in Unity either).

You can re-run **City Hall > Build Town Scene** any time — it always builds fresh into the same `Town.unity` path, so treat hand-edits to that scene as temporary unless you move them into the script or a prefab first.

## 4. Manual smoke test (optional — useful if the automatic build hits an issue)

The automatic builder in section 3 is the primary path. This manual version is smaller and slower to set up, but useful for isolating a problem if `Build Town Scene` throws an error, since it exercises the same core loop (spawn → identity → dialogue data → interaction → subtitle UI) by hand, one piece at a time:

1. **File > New Scene** (Basic 3D URP template). 
2. **GameObject > 3D Object > Plane** as ground; mark it **Static**, then bake a NavMesh over it (**Window > AI > Navigation**, or add a `NavMeshSurface` component and call Bake).
3. Empty GameObject `Systems` with `Systems.CivicDataLoader`, `Systems.TimeOfDayManager`, `Systems.PerformanceLODManager`.
4. A capsule with `NPC.NPCIdentity`, `NPC.NPCVariationController`, `NPC.NPCRoutineController`, and `Dialogue.DialogueTrigger` (`conversationId = "parent_neighbor_sidewalks"`) — or just reuse `Assets/Prefabs/Citizen_Base.prefab`, which the automatic builder already created for you.
5. `Systems.NPCSpawner` pointed at that prefab with one spawn entry (`rosterId = "parent_01"`).
6. A world-space Canvas with two TMP text children + `CanvasGroup`, and `Dialogue.DialogueUIController` wired to them.
7. `Main Camera` with `Systems.PlayerInteractor` (assign `rayOrigin` to itself) and the `Player` tag.
8. Press Play, aim at the capsule, left-click — the subtitle panel should play the "Parent & Neighbor" exchange.

**Fastest way to test on an actual headset while iterating** (no APK build needed): install **Meta Quest Link** (or Air Link) on your PC, connect/pair your headset, switch Unity's XR Plug-in Management to target the **PC, Mac & Linux Standalone** platform's OpenXR provider (in addition to Android), then just press **Play** in the Editor with the headset connected — Quest Link mirrors Play Mode straight to the headset. This is how you'll want to iterate day-to-day; save the actual `Build and Run` APK step (section 10) for when you want a standalone build that runs without a PC tethered.

## 5. Import the real asset pack and swap out the placeholders

The auto-built town uses capsule placeholders (`Assets/Prefabs/Citizen_Base.prefab`) for every citizen so the whole loop works without the paid pack. To bring in the real **Creative Characters — Modular Animated Pack**:

1. Import it from your Asset Store downloads (Window > Package Manager > My Assets, or Assets > Import Package).
2. Open one of the pack's sample prefabs and note the actual child GameObject names for each modular slot (body, head, hair, top, bottom, shoes, accessories). Every pack names these slightly differently — I couldn't inspect the real hierarchy from outside Unity, so `NPCVariationController.cs` is written against the *pattern* almost all modular-humanoid packs use, with the exact wiring left as a `[SerializeField]` list you fill in.
3. Duplicate `Citizen_Base.prefab`, replace its capsule `Body` child with the pack's rig, and re-wire `NPCVariationController`'s slot list (or, better, create one shared `NPC.NPCVariationLibrary` asset via **Assets > Create > City Hall > NPC Variation Library**, populate its pools once, and reference it from the prefab's `sharedLibrary` field).
4. Point each `NPCSpawner` (under `Town_Root > NPCSpawners`) at the new prefab, or re-run **City Hall > Build Town Scene** after editing `TownSceneBuilder.BuildCitizenPrefab()` to build the real rig in the first place.

## 6. Customizing or extending the generated town

Two options once the auto-built town is running:

- **Hand-edit `Town.unity` directly** in the Editor (move buildings, retexture, add detail) — fine for one-off polish, but remember re-running the menu command overwrites it.
- **Edit `TownSceneBuilder.cs` and re-run the menu command** — better for anything you want to keep regenerating (new NPC positions, new buildings, swapping flat roofs for real ProBuilder-modeled ones). The script is organized by zone (`BuildResidential`, `BuildCommercial`, `BuildPublicRow`, `BuildCityHallExterior`, `BuildInterior`) with small helper methods (`CreateBox`, `CreateCylinder`, `BuildInfoSign`, `MakeSpawnPoint`, ...) — follow the existing pattern for a given zone to add or move something.

## 7. Player rig, locomotion, and comfort

The auto-built scene ships a `PlayerRig`/`Main Camera` wired for desktop mouse+keyboard testing only (no locomotion component, no XR rig) — that's deliberate, since XR Origin and its locomotion providers come from an XR Interaction Toolkit **sample** you import yourself, not something a script can safely assume is already in the project. To upgrade it to VR:

1. **GameObject > XR > XR Origin (VR)** to get a correctly-configured camera rig, and either delete the auto-built `PlayerRig` or move its `PlayerInteractor`/UI-canvas references onto the new rig.
2. Add **Locomotion System**, **Continuous Move Provider** (smooth locomotion), **Teleportation Provider** + a **Teleportation Area** over the baked NavMesh/ground (the brief's "Teleport option"), and **Snap Turn Provider** or **Continuous Turn Provider** (the brief's "Comfort turning").
3. `Systems.PlayerInteractor` stays useful for Editor/desktop testing (it raycasts from whatever `rayOrigin` you assign). For the real VR build, additionally wire each controller's `XRRayInteractor` → `XRSimpleInteractable.OnSelectEntered` on the actual `IInteractable` objects — both paths call the same `Interact()` method, so nothing else needs to change.
4. Per the brief: no HUD, no minimap, no quest markers. `DialogueUIController` and `InfoPanelController` (already in the auto-built scene) are both invisible until a conversation/exhibit is actively open, and disappear immediately after — don't add a persistent status bar on top of them.

## 8. Lighting

The auto-built scene already has a directional sun light wired to `Systems.TimeOfDayManager` and streetlamp bulbs wired to `emissiveAtNight` — `TimeOfDayManager.dayLengthMinutes` defaults to a 12-minute cycle, so pressing Play and waiting (or calling `SetPeriod()` from a debug menu) already shows lighting change. To take it further:

- Bake global illumination for static geometry (**Window > Rendering > Lighting**, Baked or mixed lighting mode) once your block-out is close to final — baking after every geometry tweak will slow iteration, so leave it for realtime/mixed lighting until late in the process.
- Swap the flat primitive materials for real ones once you're past blockout — the auto-builder's `GetMaterial()` creates plain URP/Lit materials with no textures.

## 9. Performance (target: 90 FPS on-headset)

- `PerformanceLODManager` handles distance-based NPC activation/animation/audio culling automatically once NPCs are registered (which `NPCSpawner` does for you) — already wired to the player camera in the auto-built scene.
- The auto-builder already marks static geometry (buildings, streetlamps, boards — anything that doesn't move) with `StaticEditorFlags.BatchingStatic | StaticEditorFlags.NavigationStatic`, so **Static Batching** and NavMesh baking already account for it. Portal frames and UI icon markers are deliberately left non-static since they toggle/animate.
- Set up **LOD Groups** on anything with real poly count once you replace the primitive block-out with final art.
- Use **GPU Instancing** on shared materials (trees, benches, mailboxes, lamp posts) — check "Enable GPU Instancing" on the material.
- Profile early and often with the **Unity Profiler** and, once you have a build, the **Meta/Oculus Performance Lab** or **OVR Metrics Tool** — don't wait until the town is fully built to check frame time.

## 10. Building the APK

**File > Build Settings** → switch platform to **Android** → **Player Settings**: set minimum API level per your headset's requirements (Quest 2/3 typically wants API 29+), enable the OpenXR/Oculus XR plug-in under XR Plug-in Management for the Android tab, set **Texture Compression** to ASTC. **Build** (or **Build and Run** with a headset connected via USB and Developer Mode enabled) produces the `.apk`.

## Known limitations of this scaffold

- **Nothing here has compiled.** Every script — including the ~1000-line `TownSceneBuilder.cs` — was written and structurally checked (brace/paren balance across all 20 files, namespace/using consistency, quote parity) outside Unity, since there was no Editor available to actually compile any of it. Expect minor first-pass fixes: a missing `using`, an API that drifted between package versions, a component reference that needs re-wiring.
- **The single highest-risk line is in `TownSceneBuilder.BuildNavMesh()`**: it assumes `Unity.AI.Navigation.NavMeshSurface`/`CollectObjects` (the `com.unity.ai.navigation` package, version 1.1.5 per the manifest). If your installed Editor resolves a different package version with a different namespace, this is the one method most likely to need a one-line fix — everything else in the file only touches long-stable `UnityEngine`/`UnityEditor` API.
- **The generated town is primitive-geometry-only by design** — cubes, cylinders, spheres, planes, capsules, no custom meshes anywhere (see the class-level comment in `TownSceneBuilder.cs`), because a hand-authored mesh's triangle winding can't be verified without opening it in Unity, and a mis-wound mesh silently renders invisible. That's why houses have flat cap roofs instead of pitched ones and why there's no architectural detail — swap in real art once you're in the Editor.
- **`NPCVariationController`'s modular slot wiring is a guess at the real asset pack's structure** — the actual `Creative Characters` prefab hierarchy has to be inspected in the Editor after import; the script's slot system is written to be easy to point at whatever that hierarchy turns out to be.
- **Package versions in `manifest.json`** were picked to be broadly compatible with Unity 2022 LTS at time of writing; Package Manager will auto-resolve to the nearest valid version if any of these are slightly off for your installed Editor version.
- **VO audio clips are not included** — `ConversationLine.voClipResourcePath` is wired up and ready, but every line currently plays as subtitle-only until you record/place clips under `Assets/Data/Resources/Audio/VO/`.
- **Ambient audio zones (`Systems.AmbientAudioZone`) aren't placed by the auto-builder** — add trigger volumes over each district yourself and assign clips per the brief's audio spec (Residential: birds/wind/lawn mower/kids/dogs; Commercial: traffic/crosswalk beeps/chatter/coffee machines/doors; City Hall: quiet conversation/footsteps/PA/printer/HVAC).
- **The four City Hall interior doors (Council Chambers, Mayor's Office, Permit Counter, Community Engagement Office) are labeled but not interactive** — their blurb text exists only as a code comment in `BuildInterior()`, not in a JSON file, since it wasn't clear whether door blurbs belong in `CivicExhibits.json` or deserve their own data file. Easy to wire up once you decide.
